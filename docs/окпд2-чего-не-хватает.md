## Почему это важнее, чем кажется

РТС-маркет — площадка закупок, и ОКПД2 там не украшение: по нему заказчик ищет товар и по нему же строятся закупочные процедуры. Позиция без кода находится только текстовым поиском по названию.

Проверочная загрузка 05.09.2026 показала, что **площадка подбирает код сама, и мимо**. Живые примеры из карточек:

- «GIPOPO пюре 90 г Яблоко» → предложены «Чай чёрный (ферментированный)» и «Эмали»
- «ABC кондиционер д/белья 2 л» → предложен «Кондиционеры бытовые»

На пяти тысячах позиций Гуриненко это даст случайный набор кодов, и товар будут находить не те заказчики.

## Механизм в проекте уже есть

`okpd2_by_group` читается конфигурацией и применяется в `normalize.py`: код берётся из колонки позиции, затем из группы, затем из `okpd2_default`. Заполнять нечего только потому, что группы не размечены.

Готовность источников к разметке разная:

| Источник | Есть ли группа | Что делать |
|---|---|---|
| Посуда и кухня | **да**, колонка «Группа», 127 групп | заполнить `okpd2_by_group` |
| Гуриненко, Грушево | группа есть заголовками внутри листа | вычитать заголовки, как сделано для разделов Промета |
| Гуриненко, бакалея | то же, плюс бренды | то же |
| Промет | разделы каталога из гиперссылок, 100 штук | взять готовую карту из `promet.read_catalog_map` |
| ОПТ | нет | по стоп-словам либо вручную |

## Порядок, который предлагается

1. Утвердить обе таблицы по посуде и внести в `sources.yml` — 1 029 позиций, 60% источника.
2. Промет: раздел каталога уже известен для 1 722 позиций, `read_catalog_map` его отдаёт. Сопоставить сотню разделов с кодами — и закрыть самый крупный источник в той части, что реально продаётся.
3. Гуриненко: научиться читать группы-заголовки, затем разметить.

Страна происхождения — отдельный вопрос: колонки страны нет ни в одном прайсе, и заполнять её означает заявлять от себя. Площадка позиции публикует и без неё: проверочная загрузка 05.09.2026 прошла целиком, все восемь позиций в статусе «Опубликованные».
