# Сборка прайс-листов для РТС-маркет: проектное решение

Дата: 2026-09-02

## 1. Задача

Продавец работает на площадке РТС-маркет от двух юридических лиц — ООО «TLT» и ИП. Товар
поступает от нескольких поставщиков, каждый присылает прайс в собственном формате. Нужен
механизм, который превращает разнородные прайсы в файлы формата РТС, отдельно для каждого
юридического лица, и позволяет управлять тем, какой поставщик сейчас выгружается, а какой нет.

### Что входит в задачу

- Чтение прайсов поставщиков в форматах `.xlsx` и `.xls`.
- Приведение их к единому внутреннему представлению.
- Генерация файлов импорта под шаблон РТС для ООО и для ИП.
- Управление составом выгрузки на четырёх уровнях: поставщик, лист, категория, позиция.
- Проверка данных до загрузки, чтобы площадка не отбивала строки.
- Снятие с продажи позиций, пропавших у поставщика.
- Публикация фотографий на собственный сервер и подстановка ссылок.

### Что не входит

- Автоматическая загрузка файла в личный кабинет РТС. Файл готовится, загружает его человек.
- Импорт через YML. Отвергнут: включённое автообновление по ссылке запрещает загрузку Excel и
  ручное редактирование в том же прайс-листе, а два юридических лица с разной ценой потребовали бы
  двух отдельных фидов на собственном хостинге.
- Учёт заказов, остатков в реальном времени, интеграция с товароучётной системой.

## 2. Установленные факты о шаблоне РТС

Источники: страница `market.rts-tender.ru/faq-excele` и файл «Шаблон для импорта ППЛ.xlsx»,
включая его служебные листы и правила проверки данных, извлечённые из XML книги.

### Структура файла

Шаблон содержит шесть листов:

| Лист | Назначение |
|---|---|
| `Данные для импорта` | целевой лист, 27 значащих колонок, шапка занимает строки 1–2, данные с 3-й |
| `Помощь` | легенда: обязательность, назначение и правила заполнения каждой колонки |
| `Пример заполнения` | одна образцовая строка |
| `Справочник ОКПД2` | 19 802 кода |
| `Справочник единиц измерения` | 542 строки ОКЕИ: обозначение, наименование, код |
| `Словари2` | значения для выпадающих списков |

### Колонки целевого листа

| № | Буква | Заголовок | Обяз. |
|---|---|---|---|
| 1 | A | Порядковый номер позиции | нет |
| 2 | B | Внутренний идентификатор позиции из товароучетной системы(при наличии) | нет |
| 3 | C | Артикул товара или внутренний регистрационный номер товара (присваивается продавцом) | нет |
| 4 | D | Наименование позиции* (max-200 символов) | **да** |
| 5 | E | Описание позиции* (max-2000 символов) | **да** |
| 6 | F | Цена за единицу (с НДС), руб.* | **да** |
| 7 | G | Единица измерения* | **да** |
| 8 | H | Код классификатора ОКПД2 | нет |
| 9 | I | НДС | нет |
| 10 | J | Доставка транспортной компанией | нет |
| 11 | K | Доставка продавцом | нет |
| 12 | L | Самовывоз со склада продавца | нет |
| 13 | M | Укажите адрес склада для самовывоза | нет |
| 14 | N | Дополнительная информация по поставке товара (выполнения работ, оказания услуг) | нет |
| 15–19 | O–S | Ссылка на картинку 1…5 | нет |
| 20–22 | T–V | Ссылка на файл 1…3 | нет |
| 23 | W | Штрих-код (13 цифр) | нет |
| 24 | X | Страна происхождения (заполняется для товара) | нет |
| 25 | Y | Регион производства (Указывается, если Страна происхождения Россия) | нет |
| 26 | Z | Актуальность (дней) | нет |
| 27 | AA | Удалить | нет |

Заголовки в шапке объединены по вертикали (строки 1–2), кроме блока J:L, где строка 1 содержит
общий заголовок «ДЕТАЛИ ДОСТАВКИ», а строка 2 — названия трёх способов доставки. Генератор пишет
шапку в том же виде и начинает данные с третьей строки.

### Правила проверки, извлечённые из книги

| Колонка | Правило |
|---|---|
| G — единица измерения | список `'Справочник единиц измерения'!$A$2:$A$535`, то есть колонка **«Обозначение»** |
| I — НДС | список `Словари2!$D$1:$D$5` |
| J, K, L — доставка | список `Словари2!$C$1:$C$2` — значения `ДА` и `НЕТ` |
| W — штрих-код | ограничение длины текста: ровно 13 |

### Два расхождения, влияющих на результат

**Единица измерения.** Страница FAQ утверждает: «Единицы измерения указываются из справочника
полностью без сокращений». Настоящая проверка в шаблоне ссылается на колонку «Обозначение»
справочника ОКЕИ, а лист «Пример заполнения» содержит значение `ШТ`. Верным считается
**обозначение** (`ШТ`, `КГ`, `Л; ДМ3`), а не наименование (`Штука`). Инструкция на сайте вводит
в заблуждение, и следование ей привело бы к отказу по обязательному полю на всех позициях.

**«Не облагается НДС».** Лист `Словари2` содержит шесть значений НДС в диапазоне D1:D6, но
проверка колонки I ссылается только на D1:D5. Значение `Не облагается НДС`, лежащее в D6, в
проверку не попало, хотя присутствует и в словаре файла, и в FAQ, и в интерфейсе площадки.
Похоже на ошибку в шаблоне: Excel подсветит такое значение как недопустимое, но серверная
проверка при импорте, вероятно, его примет. Это единственное подходящее значение для ИП без НДС,
поэтому до первой массовой выгрузки ИП проводится проверочный импорт на 3 позициях.

### Прочие ограничения

- Не более 50 000 позиций за один импорт.
- Импорт асинхронный: файл ставится в очередь, результат приходит позже.
- Колонка B принимает только цифры (лист «Помощь»). Колонка C принимает текст и цифры.
- Изображения и файлы передаются исключительно ссылками на общедоступные ресурсы; вставка
  картинок внутрь книги площадкой не поддерживается.
- Колонка Z «Актуальность» задаёт срок жизни позиции: к дате импорта прибавляется указанное число
  дней, после чего позиция пропадает из поиска и становится недоступна для заказа.
- Колонка AA: значение `1` удаляет позицию при импорте.
- При выгрузке позиций из личного кабинета в файле появляется дополнительная колонка «Ошибки
  заполнения», куда площадка пишет причины, по которым строки не прошли.

## 3. Установленные факты о прайсах поставщиков

Разобрано семь файлов. Общей структуры нет: различаются положение шапки, наличие
строк-разделителей, число листов, набор ценовых колонок.

| Источник | Формат | Позиций | Особенности |
|---|---|---|---|
| Промет | xlsx, 25 листов | 13 756 | лист `база` — плоский перечень (артикул, наименование, ID, розничная цена, статус); прочие листы — каталог по категориям; 500 позиций без цены; статусы `T`, `C`, `Z`, `D`, `S` со значением, неизвестным на момент проектирования |
| Бринэкс | xlsx, 3 листа | 12 947 | шапка на строке 6, строка 7 — служебная нумерация колонок, данные с 8-й; листы `Автодиски` и `Автошины`; богатый набор атрибутов (производитель, диаметр, ширина, вид товара) |
| Гуриненко Бакалея | xlsx, 1 лист | 1 243 | шапка разнесена по строкам 1–2; 78 строк-разделов вперемешку с товаром; ценовые колонки «Оптовая», «Регулярная», «Промо цена», «Цена клиента»; штрих-код 13 цифр в первой колонке |
| Гуриненко Грушево | xlsx, 1 лист | 4 409 | то же, но два блока «цена + остаток» |
| Прайс-лист ОПТ | xlsx, 1 лист | 521 | шапка на строках 3–4; 62 строки-категории с нумерацией вида «1.1.1»; колонки «Закуп» и «от 100 т.руб/мес»; остатки по двум складам |
| priceopt | xls (BIFF) | 1 707 | старый бинарный формат; колонки «Код», «Группа», «Производитель», «Номенклатура», «Цена», «ИП», «ООО», «Заказ» |

### Следствия для конструкции

1. **Ни в одном прайсе нет описаний.** Поле E обязательно, значит описание генерируется.
2. **Ни в одном прайсе нет единиц измерения.** Поле G обязательно, значит единица назначается.
3. **Артикулы текстовые** (`Ту-00000406`, `S10399630407`, `UT-00213698`, `00-00001698`), а колонка B
   принимает только цифры. Нужен отдельный числовой идентификатор.
4. **Товарные строки перемешаны со служебными.** Признак товарной строки задаётся правилом на
   каждый источник.
5. **Позиция шапки плавает** — от строки 1 до строки 6. Задаётся в конфигурации.
6. Поставщик priceopt размечает позиции по ИП и ООО (1619 только ИП, 76 только ООО, 12 обе).
   Согласовано решение: разметку игнорировать, весь ассортимент грузить в обе компании.

## 4. Архитектура

Конвейер из четырёх независимых стадий. Каждая стадия имеет один вход, один выход и может
проверяться отдельно.

```
input/                         прайсы поставщиков как пришли, не редактируются
   |
   v
[1] ЧТЕНИЕ                     по конфигурации источника: лист, шапка, признак товарной строки
   |                           выход: сырые записи
   v
[2] НОРМАЛИЗАЦИЯ               маппинг колонок, чистка, фильтры, назначение единиц,
   |                           генерация описаний, стабильный числовой идентификатор
   |                           выход: мастер-каталог (единая таблица)
   v
[3] РЕНДЕР ПОД КОМПАНИЮ        наценка, НДС, доставка, актуальность, ссылки на фото,
   |                           дописывание строк на удаление
   |                           выход: строки в формате 27 колонок РТС
   v
[4] ПРОВЕРКА И ЗАПИСЬ          валидация, нарезка на части по 50 000, запись .xlsx,
                               отчёты, сохранение снимка состояния
   v
output/
```

Разделение на мастер-каталог и рендер существенно: правила площадки живут в одном месте, правила
поставщика — в другом, а различия между ООО и ИП сводятся к конфигурации компании. Добавление
поставщика не требует изменения кода; добавление третьего юридического лица — тоже.

### Структура проекта

```
input/<источник>/           прайсы поставщиков
photos/<источник>/          фотографии, имя файла — артикул с суффиксом
reference/
    template.xlsx           эталонный шаблон РТС
    okei.csv               справочник единиц измерения из шаблона
    okpd2.csv              справочник ОКПД2 из шаблона
    unit_aliases.yml       соответствие «шт», «штука», «pcs» -> ШТ
sources.yml                 реестр источников: состояние, маппинг, фильтры
companies/
    ooo_tlt.yml
    ip.yml
stoplist.csv                артикулы, исключённые вручную
state/
    id_map.csv             артикул -> числовой идентификатор РТС
    photos.json            хэш файла -> опубликованная ссылка
    last_<компания>.csv    снимок прошлой выгрузки для расчёта удалений
output/<дата>/
    ooo_tlt.xlsx
    ip.xlsx
    errors.xlsx
    report.md
src/rtsprice/
```

## 5. Управление загрузкой

Центральный механизм — реестр `sources.yml`. Каждый источник имеет **состояние**, и состояний три,
а не два.

| Состояние | Поведение |
|---|---|
| `on` | источник читается, позиции попадают в выгрузку и обновляются |
| `off` | источник не читается; его позиции из прошлой выгрузки получают `Удалить = 1` и снимаются с площадки |
| `frozen` | источник не читается, но и удаление не выполняется; позиции остаются на площадке в прежнем виде |

Различие между `off` и `frozen` отвечает двум разным ситуациям. Поставщик поднял цены и идёт
торг — ставится `frozen`, товар продолжает продаваться по прежней цене, конвейер его не трогает.
Поставщик прекратил работу — ставится `off`, и его позиции уходят с витрины при следующей сборке.

### Уровни управления

1. **Источник целиком** — поле `state` в блоке источника.
2. **Лист внутри книги** — поле `sheets`, перечень включённых листов. Для Промета с его 25 листами
   и Бринэкса с тремя это основной рычаг.
3. **Категория или группа** — списки `include_groups` и `exclude_groups`, применяемые к колонке
   группы, если она есть в прайсе.
4. **Отдельная позиция** — файл `stoplist.csv` с парами «источник, артикул».

Отдельно от состояния задаётся **направление**: поле `companies` перечисляет юридические лица,
в прайс-листы которых идёт источник. По умолчанию — оба.

### Пример записи источника

```yaml
promet:
  title: "Промет"
  state: on
  companies: [ooo_tlt, ip]
  file: "input/promet/*.xlsx"
  sheets: ["база"]
  header_row: 1
  data_starts_at: 2
  row_is_product: "price_not_empty"
  columns:
    article: "Артикул"
    name: "Наименование"
    supplier_id: "ID"
    price: "Розничная цена"
  filters:
    exclude_groups: []
  markup: 1.25
  unit_default: "ШТ"
  description_template: "{name}\nАртикул производителя: {article}"
```

Ключ верхнего уровня (`promet`) служит кодом источника и участвует в формировании
идентификаторов и путей к фотографиям, поэтому не меняется после первой выгрузки.

### Команды

```
rtsprice status                       состояние всех источников: дата прайса, число позиций, куда идёт
rtsprice build                        собрать всё включённое для обеих компаний
rtsprice build --only promet          собрать один источник
rtsprice build --skip brinex          собрать всё, кроме указанного
rtsprice build --company ip           собрать только для одного юридического лица
rtsprice check                        полная проверка без записи выходных файлов
rtsprice on|off|freeze <источник>     сменить состояние без правки конфигурации
rtsprice feedback <файл>              разобрать выгрузку из РТС с колонкой «Ошибки заполнения»
```

Команда `status` — основной инструмент контроля. Её вывод показывает по каждому источнику:
состояние, найденный файл и его дату, число товарных строк, число отфильтрованных, и в какие
прайс-листы он попадает.

## 6. Мастер-каталог

Единое внутреннее представление позиции. Поля, не найденные в прайсе, остаются пустыми и
заполняются на стадии рендера или не заполняются вовсе.

| Поле | Источник | Назначение |
|---|---|---|
| `source` | код источника | принадлежность, пути к фото |
| `article` | прайс | колонка C, имя файла фотографии |
| `rts_id` | генерируется | колонка B |
| `name` | прайс | колонка D после обрезки |
| `description` | генерируется | колонка E |
| `price_in` | прайс | закупочная цена до наценки |
| `price_includes_vat` | конфигурация источника | признак для расчёта |
| `unit` | конфигурация или прайс | колонка G |
| `okpd2` | прайс или правило по группе | колонка H |
| `barcode` | прайс | колонка W |
| `country`, `region` | прайс или конфигурация | колонки X, Y |
| `group` | прайс | фильтры, генерация описания, подбор ОКПД2 |
| `stock` | прайс | фильтр наличия |
| `attributes` | прайс | произвольные атрибуты для описания |

## 7. Идентификаторы

Колонка B принимает только цифры и служит площадке ключом для сопоставления позиции при повторном
импорте. Ошибка здесь приводит к размножению дублей на витрине, поэтому идентификатор должен быть
стабильным на всём протяжении жизни позиции.

Правило: `rts_id = prefix * 10_000_000 + порядковый номер`, где `prefix` — двузначный код
источника, назначаемый один раз в `sources.yml`. Соответствие «источник + артикул → rts_id»
хранится в `state/id_map.csv` и только пополняется. Артикул, встреченный раньше, всегда получает
прежний идентификатор; новый артикул получает следующий свободный номер.

Один и тот же `rts_id` используется в выгрузке ООО и в выгрузке ИП. Это допустимо: прайс-листы
принадлежат разным учётным записям, и пространства идентификаторов не пересекаются.

## 8. Цена и НДС

Колонка F требует цену **с НДС**. Согласовано: ООО работает с НДС 22%, ИП — без НДС.

Расчёт для ООО:

```
база = price_in, приведённая к сумме без НДС
       (если price_includes_vat, то price_in / 1.22, иначе price_in)
цена  = округлить(база * markup * 1.22)
НДС   = "Облагается НДС 22"
```

Расчёт для ИП:

```
база = price_in, приведённая к сумме С НДС
       (если price_includes_vat, то price_in, иначе price_in * 1.22)
цена  = округлить(база * markup)
НДС   = "Не облагается НДС"
```

База для ИП — фактически уплаченная поставщику сумма, а не очищенная от налога. ИП на упрощённой
системе входящий НДС не возмещает: для него эти 22% не налог, а часть себестоимости. Если считать
наценку от суммы без НДС, объявленные 100% наценки превратятся в реальные 64%, и разница уйдёт
в убыток незаметно. При равной наценке обе компании выставляют одну и ту же цену — различается
только её налоговый состав.

Наценка берётся из конфигурации компании, переопределяется на уровне источника, затем на уровне
группы товаров — побеждает самое частное правило. Рабочее значение обеих компаний — `2.0`, то есть
плюс 100% к закупочной цене. Значение `1.0` на уровне источника трактуется как «не задано» и
передаёт управление уровню компании.

Правило округления задаётся в конфигурации компании: `ruble` (вверх до целого рубля, значение по
умолчанию), `ten` (вверх до десяти рублей), `none`.

## 9. Описания

Описание обязательно, но отсутствует во всех прайсах. Формируется по шаблону из конфигурации
источника: подставляются доступные поля, отсутствующие строки выбрасываются целиком.

Для Бринэкса доступны производитель, вид товара, диаметр, ширина — описание получается
содержательным. Для остальных источников основой служат наименование, группа и бренд.

Резервное правило: если после подстановки описание пустое, в него записывается наименование
позиции. Это гарантирует, что обязательное поле заполнено, и позиция не будет отклонена.

Длина ограничивается 2000 символами, наименование — 200. Обрезка выполняется по границе слова.
Полное наименование при этом попадает в описание, поэтому информация не теряется и остаётся
доступной поиску площадки.

## 10. Фотографии

Поставщики фотографий не предоставляют. Фотографии — собственный актив, накапливаемый постепенно.

Файлы складываются в `photos/<источник>/` и именуются артикулом с суффиксом номера:
`photos/promet/S10399630407_1.jpg`. Именование по артикулу, а не по сгенерированному
идентификатору, выбрано намеренно: артикул виден в прайсе поставщика, и человек может разложить
файлы без обращения к служебным таблицам.

Обработка при сборке:

1. Найти файлы, соответствующие артикулу позиции, не более пяти.
2. Вычислить хэш содержимого и сверить с `state/photos.json`.
3. Новые и изменившиеся привести к JPEG, не более 1600 пикселей по длинной стороне и 1 МБ.
4. Загрузить по SFTP на сервер продавца, записать полученную ссылку в манифест.
5. Подставить ссылки в колонки O–S.
6. Перед записью выходного файла проверить доступность каждой ссылки запросом `HEAD`: код 200 и
   тип содержимого, начинающийся с `image/`.

Кэширование по хэшу означает, что еженедельная пересборка не превращается в перезаливку всего
архива фотографий.

Позиции без фотографий выгружаются с пустыми колонками O–S и получают изображение при следующей
сборке, когда файл появится в папке. Отдельного действия для этого не требуется.

Облачные диски (Яндекс.Диск, Google Drive, облако Mail) для хранения не подходят: их публичная
ссылка отдаёт HTML-страницу просмотра, а не файл, и площадка изображение не получит. Используется
собственный сервер продавца.

Колонки T–V («Ссылка на файл») работают по тому же механизму и предназначены для сертификатов,
паспортов и инструкций.

## 11. Проверка данных

Проверка выполняется до записи выходного файла. Цель — не допустить круга «загрузил, получил
список ошибок, чиню, загружаю снова», который на десятках тысяч позиций стоит дорого.

Правила, отклоняющие позицию:

| Проверка | Причина |
|---|---|
| наименование пустое | обязательное поле |
| описание пустое после генерации и резервного правила | обязательное поле |
| цена не число, ноль или отрицательная | обязательное поле, только цифры |
| единица измерения отсутствует в колонке «Обозначение» справочника ОКЕИ | закрытый список |
| `rts_id` не назначен или не является числом | требование колонки B |
| дубль `rts_id` внутри выгрузки | конфликт при импорте |

Правила, исправляющие значение и заносящие предупреждение в отчёт:

| Проверка | Действие |
|---|---|
| наименование длиннее 200 символов | обрезка по границе слова |
| описание длиннее 2000 символов | обрезка по границе слова |
| штрих-код не равен 13 цифрам | очистка поля |
| регион производства задан при стране, отличной от России | очистка поля |
| ОКПД2 не соответствует формату или отсутствует в справочнике | очистка поля; площадка подберёт код сама |
| ссылка на изображение недоступна | исключение ссылки |
| значение НДС вне словаря | подстановка значения по умолчанию для компании |

Отклонённые позиции выгружаются в `output/<дата>/errors.xlsx` с указанием источника, артикула,
поля и причины. Исправление вносится в конфигурацию источника, а не в выходной файл: выходной файл
пересоздаётся при каждой сборке и правки в нём теряются.

## 12. Снятие с продажи и отчёт о разнице

После успешной сборки состав выгрузки сохраняется в `state/last_<компания>.csv` — полная копия
записанных строк.

При следующей сборке идентификаторы, присутствовавшие в снимке и отсутствующие в новой выгрузке,
дописываются в конец файла строкой из снимка с проставленным `Удалить = 1`. Строка копируется
целиком, а не собирается из одного идентификатора: требования площадки к составу полей в строке
удаления не документированы, и полная строка заведомо безопасна.

Источники в состоянии `frozen` из этого расчёта исключаются: их позиции отсутствуют в новой
выгрузке, но удалять их не следует.

Отчёт `output/<дата>/report.md` содержит по каждому источнику число прочитанных, отфильтрованных и
принятых позиций с указанием причин отсева, а также сводку изменений: сколько позиций новых, у
скольких изменилась цена и на сколько, сколько снимается с продажи. Отчёт читается перед загрузкой
файла и служит последней возможностью заметить, что поставщик прислал испорченный прайс.

## 13. Актуальность и условия поставки

Колонки J–N и Z одинаковы для всех позиций одной компании и задаются в её конфигурации:

```yaml
delivery:
  by_carrier: "ДА"
  by_seller: "ДА"
  pickup: "ДА"
warehouse_address: "..."
delivery_terms: "..."
validity_days: 21
```

Значение `validity_days` выбирается с запасом относительно периодичности обновления прайсов. При
еженедельной сборке 21 день означает: если выгрузка пропущена дважды подряд, позиции сами уйдут из
поиска, и площадка не будет продавать товар по цене трёхнедельной давности.

## 14. Проверочный импорт

До первой массовой выгрузки выполняется импорт файла из трёх позиций, по одной на каждый спорный
случай. Проверяется:

1. Принимает ли площадка единицу измерения в виде обозначения (`ШТ`).
2. Принимает ли площадка значение `Не облагается НДС`, отсутствующее в диапазоне проверки
   шаблона. Это блокирующий вопрос для выгрузки ИП.
3. Совпадает ли ожидаемое поведение колонки B: получает ли позиция при повторном импорте того же
   идентификатора обновление, а не дубль.

Результат фиксируется в этом документе, после чего запускается полная выгрузка.

### Результат проверки от 03.09.2026, кабинет ИП, прайс-лист «Прайс тест»

Загружен файл из трёх позиций (автошины Бринэкса). Импорт принят, позиции опубликованы под
номерами объявлений 37527544–37527546.

1. **Единица измерения `ШТ` принята.** В карточке отображается «9 602,00 ₽ / шт.». Справка на
   сайте, требующая писать единицу полностью, вводит в заблуждение: правило проверки в самом
   шаблоне ссылается на колонку обозначений, и площадка ведёт себя именно так.
2. **Значение `Не облагается НДС` принято.** В карточке отображается «Не облагается НДС».
   Обрезанный до пяти значений диапазон проверки в шаблоне — недосмотр РТС, серверная проверка
   значение принимает. Блокирующий вопрос для выгрузки ИП снят.

Наблюдение: при пустых полях адреса склада и условий поставки площадка проставила «Адрес
доставки: Все регионы». Если требуется иное, это задаётся в `companies/*.yml`.

## 15. Вопросы к поставщикам

Требуют уточнения у контрагентов и не блокируют разработку — до получения ответов действуют
указанные умолчания:

- Промет: значение статусов `T`, `C`, `Z`, `D`, `S` на листе `база`. До ответа статусы не
  используются как фильтр, отсекаются только позиции без цены.
- Промет: 500 позиций без цены — сняты с производства или цена по запросу. До ответа отсекаются.
- Гуриненко: какая из колонок «Оптовая», «Регулярная», «Промо цена», «Цена клиента» является
  рабочей закупочной. До ответа используется «Цена клиента» как наиболее конкретная.
- Прайс-лист ОПТ: соотношение колонок «Закуп» и «от 100 т.руб/мес». До ответа используется «Закуп».
