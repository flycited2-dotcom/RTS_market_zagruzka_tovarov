# Сборка прайс-листов для РТС-маркет

## Установка

Один раз, перед первым запуском, из корня проекта:

```
pip install -e .
```

Без этого шага первая же команда ежедневной работы завершится ошибкой
`No module named rtsprice`: пакет лежит в `src/`, и сам по себе интерпретатор его не находит.

После установки команды `python -m rtsprice ...` вызываются из любого каталога, но проект
они ищут в текущем. Запущенная не из корня команда без `--root` не найдёт `sources.yml`,
поэтому из другого каталога корень указывается явно:

```
python -m rtsprice --root C:\путь\к\RTS_tender check
```

Команды ниже записаны для запуска из корня проекта.

## Ежедневная работа

1. Положить свежий прайс поставщика в `input/<источник>/`, старый удалить или оставить —
   берётся самый свежий файл.
2. Проверить, что получится: `python -m rtsprice check`
3. Собрать файлы: `python -m rtsprice build`
4. Прочитать `output/<дата>/report.md` — там доля отсева по каждому поставщику и что изменилось.
5. Загрузить `output/<дата>/ooo_tlt.xlsx` и `output/<дата>/ip.xlsx` в личные кабинеты.
6. После успешной загрузки подтвердить её: `python -m rtsprice uploaded ooo_tlt`
   и `python -m rtsprice uploaded ip`.

Шаг 6 обязателен. Строка удаления — указание площадке, а не свершившийся факт: пока загрузка не
подтверждена, конвейер хранит её в `state/pending_delete_<компания>.csv` и дописывает в каждый
следующий файл. Без этого вторая сборка того же дня перезаписала бы файл без строк удаления, и
позиции, которых у поставщика больше нет, остались бы в продаже по старой цене. Повторить
удаление уже снятой позиции безвредно — площадка её просто не найдёт.

Подтверждайте загрузку сразу же, до того как менять состояние источников. Если между загрузкой и подтверждением
изменится состояние источника, можно потерять информацию об удалении, которое площадка уже применила.

Отчёт и вывод команды показывают, сколько удалений ждут подтверждения.

## Управление составом

| Команда | Что делает |
|---|---|
| `python -m rtsprice status` | показать все источники, их состояние и дату прайса |
| `python -m rtsprice off <источник>` | снять позиции источника с площадки |
| `python -m rtsprice freeze <источник>` | заморозить: не обновлять и не удалять |
| `python -m rtsprice on <источник>` | вернуть в работу |
| `python -m rtsprice build --only promet` | собрать один источник |
| `python -m rtsprice build --company ip` | собрать только для ИП |
| `python -m rtsprice uploaded <компания>` | файл загружен: забыть неподтверждённые удаления |

Отдельные позиции исключаются через `stoplist.csv` — строка `источник,артикул`.

## Фотографии

Класть в `photos/<источник>/<артикул>_1.jpg`, до пяти файлов на позицию. Ссылки подставляются
сами при следующей сборке.

Чтобы площадка могла их скачать, снимки публикуются на ваш сервер. Настройки лежат в
`photos.yml`, который в git не попадает. Сейчас там: сервер `212.116.115.150:2222`, каталог
`/opt/oasis/rts-photos/`, публичный адрес `https://splithome.ru/rts-photos`. Отдачу этого пути
обслуживает отдельный блок `location /rts-photos/` в `/etc/nginx/sites-enabled/splithome.ru`.

Если понадобится настроить заново, образец — `photos.yml.example`.

Пароли не поддерживаются намеренно — только ключ. Пароль в конфигурации утекает в историю
команд и в резервные копии, ключ не утекает.

Пока `photos.yml` отсутствует, сборка работает как раньше и оставляет колонки изображений
пустыми. Команда `check` соединение не открывает: она обязана быть без побочных действий.

## Известные особенности источников

- **priceopt** — заголовок колонки наименования содержит дату выгрузки
  (`Номенклатура ДД-ММ-ГГ`) и меняется при каждой присылке поставщика. При обновлении файла
  нужно поправить `columns.name` в `sources.yml` под текущий заголовок — иначе сборка упадёт
  с `KeyError`, который перечислит доступные заголовки листа.
- **Гуриненко, Грушево** — в шапке дважды встречается заголовок «Цена клиента» (для двух разных
  складов): в каждой позиции ровно одна из двух колонок заполнена, вторая пуста. Читалка это
  учитывает: при повторе заголовка берётся первое непустое значение среди всех колонок с этим
  заголовком, так что позиция получает цену независимо от того, на каком из двух складов она
  фактически лежит.
- **Гуриненко, бакалея/Грушево** — товарная строка определяется по непустой цене, а не по
  13-значному штрих-коду: у части позиций код формата EAN-8, UPC или GTIN-14 (`40111216`,
  `14600699510922`), и правило `barcode13` молча выбрасывало их — 18 позиций в бакалее и 59
  в Грушево. Строки-разделы цены не имеют, поэтому отделяются правилом ровно так же.
- **Бринэкс, автодиски/автошины** — остаток на складе часто указан как `>40` или `>100`
  вместо числа: это «не меньше сорока», то есть лучший склад, а не отсутствие данных.
  Конвейер снимает ведущий знак сравнения при разборе остатка, поэтому `min_stock: 1`
  включён на обоих листах. Для цены такой разбор не применяется: цена со сравнением —
  не цена, и позиция правильно отклоняется.

## Важное

- Не редактировать `state/id_map.csv` — он связывает артикулы с идентификаторами позиций на
  площадке. Его потеря приводит не к дублям, а к столкновениям: нумерация начинается заново,
  идентификатор, который площадка знает за одним товаром, достаётся другому, и следующий импорт
  перепишет существующие позиции чужими названиями и ценами. Сборка отказывается работать, если
  карта пуста, а снимок выгрузки — нет.
- **Каталог `state/` нужно резервировать.** Он не попадает в git и содержит единственную копию
  карты идентификаторов и списка неподтверждённых удалений — потеря резервной копии означает потерю обоих.
  Восстановить их из прайсов поставщиков невозможно.
- Не править файлы в `output/` — они пересоздаются при каждой сборке.
- **Нет `report.md` — не загружать.** Отчёт пишется последним, уже после прайс-листов, поэтому
  его отсутствие в каталоге дня означает, что сборка упала на полпути. Файлы `.xlsx` при этом
  на месте и выглядят целыми, но состав их неизвестен. Разберитесь с ошибкой и соберите заново.
- **Сужать `companies` у источника после первой выгрузки нельзя.** Убранная из списка компания
  перестаёт получать позиции источника, но её снимок продолжает их помнить, а снять с продажи
  их уже нечем: источник для этой компании больше не пересобирается. Позиции останутся на
  витрине навсегда. Чтобы вывести источник из продажи, переводите его в `off` — он снимет
  позиции у всех компаний, — и только потом правьте конфигурацию.
- Наценка задаётся в `companies/*.yml` и уточняется в `sources.yml`.
